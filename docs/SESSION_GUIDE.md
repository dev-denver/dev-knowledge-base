# Session Guide

## session의 역할

session은 실제 학습 과정의 원본 기록이다. 질문, 답변, 코드, 오류, 시행착오, 결정 과정, 미해결 질문을 있는 그대로 남긴다. 나중에 note로 정제될 원재료이므로, 당시 사고 과정이 드러나야 한다.

## 파일명 규칙

`sessions/YYYY-MM-DD-topic-slug.md`

- `YYYY-MM-DD`는 학습을 진행한 날짜.
- `topic-slug`는 소문자와 하이픈으로 구성된 주제 요약 (예: `java-sealed-class`).
- 같은 날 같은 주제로 여러 세션을 진행해도 파일을 나누지 않고 기존 파일에 이어서 기록하는 것을 우선한다. 완전히 다른 하위 주제라면 slug를 구분해 새 파일을 만든다.

## 현재 학습 session을 판단하는 기준

"기록해줘", "이어서 공부하자" 같은 요청을 받으면 다음 우선순위로 현재 session을 판단한다.

1. 오늘 날짜(`YYYY-MM-DD`)로 시작하고 같은 주제를 다루는 파일이 있으면 그것이 현재 session이다.
2. 오늘 날짜의 session이 없고 사용자가 이전 주제를 이어간다고 명시하면, 가장 최근의 관련 session을 참고해 오늘 날짜로 새 session을 만든다.
3. 어떤 세션인지 애매하면 추측으로 새 파일을 만들지 말고 사용자에게 짧게 확인한다.

## 학습 목표 작성법

- 그 세션에서 확인하고 싶은 구체적인 질문이나 목표를 적는다.
- "OO를 공부한다" 같은 막연한 목표보다 "OO가 왜 필요한지, XX와 어떻게 다른지 확인한다"처럼 검증 가능한 형태로 적는다.

## 질문과 답변 기록법

- 실제로 오간 질문과 핵심 답변을 `Q.` 단위로 남긴다.
- 답변은 요약하되, 핵심 근거나 예외 조건은 생략하지 않는다.
- 외부 자료를 참고했다면 URL과 확인 날짜(`YYYY-MM-DD`)를 근거 항목에 남긴다.

## 코드와 실행 결과 기록법

- 실제로 실행한 코드와 그 결과(출력, 에러 메시지 포함)를 그대로 남긴다.
- 코드 블록에는 언어 또는 파일명을 명시한다.
- 동작하지 않은 코드도 삭제하지 말고 "동작하지 않음"으로 표시해 남긴다 — 시행착오 자체가 기록의 가치다.

## 오류와 시행착오 기록법

- 발생한 오류 메시지, 잘못된 가정, 원인, 해결 과정을 순서대로 남긴다.
- 문제가 해결되지 않았다면 "미해결"로 명시하고 미해결 질문 섹션에도 옮겨 적는다.

## 확실하지 않은 내용을 표시하는 방법

- 검증되지 않았거나 추측으로 적은 내용에는 문장 끝에 `(확인 필요)`를 붙인다.
- 이렇게 표시된 내용은 note로 승격할 때 그대로 사실처럼 옮기지 않는다.

## 미해결 질문과 다음 작업 관리법

- 세션 중 답을 찾지 못한 질문은 미해결 질문 섹션에 체크박스로 남긴다.
- 다음에 이어서 할 작업은 다음 작업 섹션에 남긴다.
- 이후 세션에서 답을 찾으면 원래 항목을 체크하거나 답변을 추가하고, 항목 자체를 삭제하지 않는다.

## session 완료 기준

- session은 "완료"라는 상태가 필수는 아니다. frontmatter의 `status`를 `in-progress` / `done` / `abandoned` 중 실제 상태에 맞게 갱신한다.
- 그날 학습을 마무리할 때는 오늘의 결론과 미해결 질문을 최신 상태로 갱신한다 ("오늘 공부 마무리해줘" 패턴 참고).

## templates/session-template.md 사용법

- 새 session은 `templates/session-template.md`를 복사해 시작한다. `npm run new:session -- <category> "<topic>"` 명령이 이 과정을 자동화한다.
- 템플릿의 `{{TOPIC}}`, `{{DATE}}`, `{{CATEGORY}}`는 실제 값으로 치환한다.
- 템플릿의 섹션 제목과 순서는 유지한다. 특정 세션에서 내용이 없는 섹션은 "해당 없음"으로 남기고 섹션 자체를 삭제하지 않는다.
