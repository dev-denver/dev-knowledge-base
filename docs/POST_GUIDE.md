# Post Guide

## post의 역할

post는 note를 바탕으로 외부 독자가 읽을 수 있게 다시 쓴 완결된 블로그 글이다. session이나 note의 학습 과정 문체를 그대로 옮기지 않고, 배경지식이 없는 독자도 따라올 수 있게 새로 구성한다.

## 독자와 글의 목적을 먼저 정하는 방법

작성을 시작하기 전에 다음을 명확히 한다.

- 이 글을 읽을 독자가 이미 알고 있다고 가정할 수 있는 지식 수준
- 글을 다 읽었을 때 독자가 할 수 있어야 하는 것 (이해, 적용, 선택 등)

이 판단이 서지 않으면 임의로 정하지 말고 사용자에게 확인한다.

## note를 우선 자료로 사용하는 원칙

- post의 핵심 내용은 `notes/`의 검증된 note를 우선 자료로 사용한다.
- session은 note에 없는 배경 맥락이나 구체적 예시가 필요할 때만 보조적으로 참고한다.
- note에 없는 내용을 session에서 가져와 post에 새로운 사실로 추가하는 경우, 그 내용이 검증된 것인지 다시 확인한다.

## 권장 글 구조

`templates/post-template.mdx`의 구조를 따른다.

1. 문제 또는 학습 배경
2. 핵심 개념
3. 단계별 설명
4. 실행 가능한 예제
5. 흔한 실수와 주의점
6. 선택 기준 또는 실무 적용
7. 마무리
8. 학습 자료 (note/session 링크)
9. 외부 참고 자료

## 제목과 description 작성 기준

- 제목은 글의 핵심 주제와 관점이 드러나야 한다. note 제목을 그대로 복사하지 않고 독자 관점으로 다듬는다.
- `description`은 한두 문장으로 이 글을 읽으면 무엇을 얻는지 설명한다.

## 코드 예제 작성 기준

- note나 session에서 이미 검증된 예제를 우선 사용한다.
- 새로 작성하는 예제는 실제로 동작을 확인한 뒤 싣는다. 확인하지 못했다면 그 사실을 감추지 않고 사용자에게 보고한다.
- 코드 블록에는 언어를 명시한다.

## frontmatter 필드 설명

```yaml
---
title: "글 제목"
date: "YYYY-MM-DD"
description: "글의 핵심 내용을 설명하는 한두 문장"
tags: ["tag-a", "tag-b"]
draft: true
---
```

- `title`: 글 제목 (문자열)
- `date`: 작성일, `YYYY-MM-DD` 형식
- `description`: 한두 문장 요약
- `tags`: 문자열 배열, 최소 1개 이상 권장
- `draft`: boolean. 발행 준비가 되지 않은 글은 항상 `true`

## draft 필드 변경 기준

- 새로 생성하는 post는 항상 `draft: true`로 시작한다.
- 사용자가 "게시 준비해줘", "최종 검토해줘"처럼 명시적으로 요청하지 않는 한 `false`로 바꾸지 않는다.
- 품질 체크리스트를 통과하고 사용자가 발행 준비를 명시적으로 요청했더라도, 이 저장소는 실제 publish를 수행하지 않는다. `draft` 값 변경은 "발행 준비 완료" 표시일 뿐이다.

## note와 session 출처 링크 규칙

- 글 마지막 "학습 자료" 섹션에 이 글의 근거가 된 note와 session을 저장소 상대 경로로 모두 나열한다.
- 근거가 여러 개면 모두 나열하고, 일부만 골라 생략하지 않는다.

## 특정 블로그 엔진에 종속되지 않게 작성하는 원칙

- 특정 프레임워크의 커스텀 컴포넌트, 커스텀 MDX import, 플러그인 전용 문법을 사용하지 않는다.
- 표준 Markdown/MDX 문법(제목, 목록, 코드 블록, 링크, 표)만 사용한다.
- 이미지가 필요하면 일반 Markdown 이미지 문법을 사용하고 특정 CDN이나 컴포넌트에 의존하지 않는다.

## templates/post-template.mdx 사용법

- 새 post는 `templates/post-template.mdx`의 구조를 그대로 복사해 시작한다.
- `{{TITLE}}`, `{{DATE}}`, `{{DESCRIPTION}}`을 실제 값으로 치환하고 `tags`를 채운다.
- 섹션 제목과 순서를 유지한다. 내용이 없는 섹션은 임의로 삭제하지 않고 사용자와 상의한다.
